# 中文 ChatGPT 风格侧栏与数学公式渲染设计

日期：2026-09-04

## 目标

将 Side Chat Companion 的所有用户可见界面统一为中文，把右侧聊天栏调整为接近 ChatGPT 网页版的视觉和交互，并让模型回复中的常见 Markdown LaTeX 数学公式正确显示。

本次成功标准：

- 侧栏、设置页、隐私与权限说明、状态和错误提示均使用中文。
- AI 回复直接铺在侧栏背景上，用户消息使用右侧圆角气泡，输入区采用 ChatGPT 风格的悬浮圆角容器。
- `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]` 均能渲染；代码块和行内代码中的同类字符保持原样。
- 无效或尚未接收完整的公式不会破坏整条流式回复。
- 不改变 API、权限、上下文预算、附件、历史记录和会话隔离行为。

## 界面设计

采用已批准的 A 方案“ChatGPT 原生风”。

### 侧栏

- 深色背景与 ChatGPT 网页版协调，弱化消息卡片边框。
- AI 回复直接显示在背景上；用户消息靠右显示为圆角气泡。
- 引用内容使用细绿色左边框，作为当前问题的轻量上下文提示。
- 顶栏显示“侧边对话”，操作为“清空”和“关闭”。
- 上下文摘要改为中文，显示已读取消息数、目标服务、模型和预计上下文词元。
- 输入框占据底部主要空间，提示语为“针对所选内容提问……”，发送操作使用上箭头图标并提供中文无障碍名称。
- “仅在需要时压缩旧上下文”保留原行为，文案统一为中文。
- 调整宽度、关闭后恢复页面边距、加载历史和失败重试等现有交互保持不变。

### 设置页及全局文案

- 设置页标题、数据使用说明、字段标签、按钮、本地数据管理、成功状态和错误提示全部翻译为中文。
- Base URL、API、模型名称、DeepSeek 等行业术语或用户填写值保留原文，避免含义模糊。
- 现有同意流程、API 密钥会话存储和端点授权流程不变。

## 数学公式渲染

### 方案

本地打包 KaTeX、KaTeX 样式及字体，不从 CDN 或其他远程地址加载资源。KaTeX 官方说明浏览器渲染需要配套样式和字体目录，因此构建产物会包含这些静态资源：https://katex.org/docs/browser

### 数据流

1. 模型回复以原始 Markdown 文本进入侧栏渲染器。
2. 渲染器识别四类公式定界符，同时跳过 fenced code block 和行内代码。
3. 普通 Markdown 继续由 `marked` 转换，并继续经过现有 DOMPurify 白名单过滤。
4. 安全过滤完成后，再由本地 KaTeX 将已识别的公式节点转换为受信任的公式 DOM。
5. 块公式居中并允许横向滚动；行内公式随正文排版。

这个顺序避免 `marked` 先把 `\[`、`\]` 等反斜杠当作 Markdown 转义符吃掉，也避免为了保留 KaTeX 输出而放宽未经处理的原始 HTML 白名单。

### 错误处理

- 尚未闭合的流式公式暂时按原文显示；收到闭合定界符后自动转为公式。
- KaTeX 无法解析的表达式保留转义后的原始 LaTeX，不抛出错误，也不影响同一消息的其他内容。
- 原始回复中的 `<script>`、事件属性、危险链接、SVG、表单与媒体元素继续被移除。

## 构建与权限

- 增加 KaTeX 运行依赖。
- 构建脚本将 KaTeX CSS 和所需字体复制到 `dist`。
- manifest 仅把 KaTeX 静态资源暴露给现有的 `https://chatgpt.com/*` 内容脚本页面。
- 不增加新的网络权限、API 端点或远程资源。
- 不迁移或清除任何现有加密历史记录。

## 测试与验证

先增加失败测试，再实施代码修改：

- 单元测试覆盖四类公式定界符、行内与块级排版、代码区域跳过、无效与不完整公式回退。
- 保留并扩展 Markdown XSS、安全链接和危险元素过滤测试。
- 侧栏测试覆盖中文标题、按钮、提示、状态和 ChatGPT 风格消息结构。
- 设置页及错误映射测试覆盖全部用户可见中文文案。
- manifest 和构建测试确认 KaTeX CSS、字体与资源声明完整。
- 运行 typecheck、完整单元测试、生产构建、打包、diff 检查和 Playwright E2E。
- 最后重新加载生产版 `dist`，在真实 ChatGPT 对话中使用 DeepSeek 验证流式公式、普通 Markdown、侧栏历史和超过 30 秒的回复。

## 非目标

- 不重新设计 ChatGPT 主页面。
- 不增加主题切换、自定义颜色、语言切换或新的模型配置项。
- 不改变消息提取、上下文压缩、附件读取或供应商请求协议。
- 不修改历史记录 schema。
